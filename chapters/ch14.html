Hardware Wallet

ตลอดเล่มนี้ ผู้ที่ถือ private key คือผู้มีสิทธิ์ใช้เหรียญ ไม่มีธนาคารให้โทรไปอายัดบัญชี และธุรกรรม (transaction) ที่เข้าบล็อกแล้วย้อนกลับไม่ได้ บทนี้ตอบคำถามเชิงปฏิบัติว่าจะเก็บ private key อย่างไรให้ไม่หายและไม่โดนขโมย เนื้อหาเริ่มจากสิ่งที่ wallet เก็บจริง ต่อด้วยเกณฑ์แบ่ง hot wallet กับ cold wallet วิธีสำรอง key ทุกดอกด้วย seed phrase (BIP39) และ HD wallet (BIP32 / BIP44) หลักการที่ทำให้ hardware wallet ลงลายเซ็นได้โดยไม่เปิดเผย key และภัยที่ผู้ใช้เจอบ่อยที่สุด

ในบทนี้
  1. เริ่มจากโจทย์: เมื่อไม่มีใครกู้บัญชีคืนให้
  2. สิ่งที่ wallet เก็บคือ private key ไม่ใช่ตัวเหรียญ
  3. Hot wallet กับ Cold wallet
  4. Seed phrase (BIP39) และ HD wallet (BIP32 / BIP44)
  5. หลักการของ Hardware wallet: ลงลายเซ็นธุรกรรมภายในอุปกรณ์ โดย key ไม่ออกจากเครื่อง
  6. ภัยที่พบบ่อยและวิธีป้องกัน
  7. สรุปท้ายบท
  8. แบบฝึกหัด

เริ่มจากโจทย์: เมื่อไม่มีใครกู้บัญชีคืนให้

ถ้าลืมรหัสผ่านแอปธนาคาร เราไปที่สาขาพร้อมบัตรประชาชนแล้วตั้งรหัสใหม่ได้ ถ้ามีคนขโมยบัตรไปรูด ธนาคารอายัดบัตรและอาจคืนเงินให้ ทั้งสองกรณีแก้ได้เพราะมีตัวกลาง (trusted third party) ที่รู้ว่าเงินเป็นของใคร บทที่ 1 อธิบายว่า Bitcoin ตัดตัวกลางนี้ออก และบทที่ 0 อธิบายว่าเครือข่ายรู้จักเจ้าของจากลายเซ็นดิจิทัล (digital signature) ที่สร้างด้วย private key เท่านั้น private key จึงทำหน้าที่เป็นทั้งบัตรประชาชน รหัสผ่าน และลายมือชื่อในคราวเดียว

เจ้าของเหรียญจึงเจอความเสี่ยงสองแบบ และทางแก้ของสองแบบนี้ขัดกันเอง

  • key หาย (loss): ถ้าไม่มีสำเนาของ private key ดอกนั้นเหลืออยู่เลย เหรียญยังอยู่บน chain แต่ไม่มีใครลงลายเซ็นใช้เหรียญได้อีก ผลจึงเท่ากับเหรียญหายไปถาวร ทางแก้ที่ตรงที่สุดคือทำสำเนาไว้หลายชุด
  • key โดนขโมย (theft): ถ้าคนอื่นได้สำเนาไป เขาโอนเหรียญออกได้ทันที และไม่มีใครย้อนธุรกรรมให้ ทางแก้ที่ตรงที่สุดคือเก็บไว้ที่เดียวและไม่ให้ใครเห็น

ยิ่งทำสำเนามาก โอกาสหายก็ยิ่งน้อย แต่โอกาสรั่วก็ยิ่งมาก โจทย์นี้ยังมีเงื่อนไขอีกข้อ คือ key ต้องพร้อมลงลายเซ็นทุกครั้งที่เจ้าของต้องการจ่ายเงิน key จึงต้องอยู่ในอุปกรณ์ที่ใช้งานได้ จะเก็บซ่อนไว้อย่างเดียวไม่ได้ หัวข้อในบทนี้ตอบโจทย์นี้ทีละส่วนตามตารางด้านล่าง

14.1สิ่งที่ wallet เก็บคือ private key ไม่ใช่ตัวเหรียญ

ทำไมต้องแยกให้ออก

คำว่า wallet ชวนให้คิดว่าเหรียญอยู่ในโปรแกรม เหมือนเงินสดอยู่ในกระเป๋าสตางค์ ถ้าเข้าใจแบบนี้ ผู้ใช้อาจตัดสินใจผิดได้สองแบบ แบบแรกคือคิดว่าโทรศัพท์หายแล้วเหรียญหายตามไปด้วย แบบที่สองคือคิดว่าลบแอปทิ้งแล้ว คนที่แอบคัดลอก key ไปก่อนหน้านั้นจะใช้เหรียญไม่ได้ ข้อเท็จจริงคือเหรียญไม่ได้อยู่ในอุปกรณ์ใดเลย

  • Bitcoin: เหรียญคือ UTXO ที่ทุก full node บันทึกไว้ใน UTXO set (บทที่ 4) แต่ละก้อนมีเงื่อนไขปลดล็อก (locking script) ที่ผูกกับ public key หรือ address
  • Ethereum: ยอด ETH เป็นตัวเลขของบัญชี EOA ใน world state (บทที่ 5) และ address ของ EOA คำนวณมาจาก public key

สิ่งที่ wallet เก็บคือ private key สำหรับลงลายเซ็นปลดล็อกเหรียญเหล่านั้น wallet จึงคล้ายพวงกุญแจมากกว่ากระเป๋าเงิน ส่วนยอดเงินที่แอปแสดง แอปก็ถามมาจากโหนดอีกทีหนึ่ง

งานของ wallet และงานที่ต้องใช้ private key

งานต้องใช้ private key หรือไม่หมายเหตุ
สร้างกุญแจคู่และ addressใช้สร้าง private key แล้วคำนวณ public key และ address (บทที่ 0)
แสดงยอดและประวัติไม่ใช้ถามโหนดด้วย address
สร้างธุรกรรมไม่ใช้ได้ธุรกรรมที่ยังไม่มีลายเซ็น (unsigned transaction) ฝั่ง Bitcoin ต้องเลือก UTXO ใส่เงินทอน (change) และค่าธรรมเนียม (fee) ฝั่ง Ethereum ต้องใส่ nonce, gas และ data
ลงลายเซ็นใช้ขั้นเดียวของการใช้จ่ายที่ต้องใช้ private key
ส่งธุรกรรมเข้าเครือข่าย (broadcast)ไม่ใช้ส่งให้โหนดกระจายต่อ

ในตาราง งานที่ต้องใช้ private key มีเพียงสองงาน งานแรกคือสร้าง key ทำครั้งเดียวตอนตั้ง wallet งานที่สองคือลงลายเซ็น ต้องทำทุกครั้งที่จ่ายเงิน งานที่เหลือใช้เพียง public key หรือ address ก็พอ hardware wallet ในหัวข้อ 14.4 อาศัยข้อสังเกตนี้ ถ้าให้อุปกรณ์อีกเครื่องสร้าง key และลงลายเซ็นแทน คอมพิวเตอร์ที่ต่ออินเทอร์เน็ตก็ทำงานที่เหลือได้โดยไม่ต้องเห็น key เลย

Custodial กับ Non-custodial

ผู้ใช้จำนวนมากซื้อเหรียญผ่านศูนย์ซื้อขาย (exchange) แล้วฝากไว้ในบัญชีของ exchange ในกรณีนี้ exchange เป็นผู้ถือ private key ส่วนผู้ใช้มีเพียงตัวเลขในฐานข้อมูลของ exchange เหมือนยอดเงินฝากธนาคาร wallet แบบนี้เรียกว่า custodial wallet ส่วน wallet ที่ผู้ใช้ถือ key เองเรียกว่า non-custodial wallet หรือ self-custody

Custodial (ฝากไว้กับ exchange)Non-custodial (ถือ key เอง)
ผู้ถือ private keyผู้ให้บริการผู้ใช้
ลืมรหัสผ่านติดต่อผู้ให้บริการเพื่อกู้บัญชีได้ถ้าไม่มี seed phrase ก็กู้ไม่ได้
ผู้ให้บริการล้มละลายหรือโดนเจาะผู้ใช้อาจไม่ได้เงินคืนไม่กระทบ
ภาระของผู้ใช้น้อยมาก ต้องสำรองและป้องกัน key เอง

custodial wallet ทำให้ตัวกลางกลับมาอีกครั้ง ทั้งที่บทที่ 1 พยายามตัดตัวกลางออก ตัวอย่างที่มักยกกันมีสองกรณี Mt. Gox ปิดตัวในปี 2014 และรายงานว่า BTC ของลูกค้าหายไปหลายแสนเหรียญ ส่วน FTX ล้มละลายในปี 2022 สำนวนที่ใช้กันในวงการคือ "Not your keys, not your coins" ถ้าไม่ได้ถือ key เอง สิ่งที่มีอยู่คือคำสัญญาของผู้ให้บริการว่าจะจ่ายคืน ไม่ใช่ตัวเหรียญ

ประเด็นที่ข้อสอบชอบถาม "ถ้า hardware wallet พังหรือหาย เหรียญหายหรือไม่" คำตอบคือไม่หาย ถ้ายังมี seed phrase เพราะเหรียญอยู่บน chain เจ้าของซื้ออุปกรณ์ใหม่หรือใช้ wallet อื่นที่รองรับ BIP39 แล้วกู้คืนจาก seed phrase ก็ได้ key ชุดเดิมกลับมา ในทางกลับกัน ถ้าคนอื่นได้ seed phrase ไป อุปกรณ์ที่ยังอยู่ในมือก็ไม่ช่วยอะไร เพราะเขาใช้เหรียญได้จากอุปกรณ์ของเขาเอง

14.2Hot wallet กับ Cold wallet

ทำไมต้องแบ่ง

key ที่ใช้จ่ายเงินทุกวันต้องอยู่ในอุปกรณ์ที่หยิบใช้ได้ทันที เช่น โทรศัพท์หรือเบราว์เซอร์ แต่อุปกรณ์ที่ต่ออินเทอร์เน็ตเปิดช่องให้ผู้โจมตีเข้ามาจากระยะไกล malware อาจอ่านไฟล์ wallet หรือดักรหัสผ่านที่พิมพ์ เว็บปลอมอาจหลอกให้ลงลายเซ็น ส่วนเงินเก็บระยะยาวแทบไม่ต้องลงลายเซ็นเลย จึงไม่มีเหตุผลให้รับความเสี่ยงแบบเดียวกัน หลักนี้เหมือนพกเงินสดติดกระเป๋าเท่าที่ใช้รายวัน และเก็บเงินก้อนใหญ่ไว้ในตู้เซฟ เกณฑ์ที่ใช้แบ่งมีข้อเดียว คือ private key อยู่บนอุปกรณ์ที่ต่ออินเทอร์เน็ตหรือไม่

private key อยู่ที่อุปกรณ์ที่ต่ออินเทอร์เน็ตอุปกรณ์หรือสื่อที่ไม่ต่ออินเทอร์เน็ต
ตัวอย่างMetaMask (browser extension), wallet บนมือถือ, Bitcoin Core บนคอมพิวเตอร์ที่ออนไลน์, hot wallet ของ exchangeHardware wallet, คอมพิวเตอร์ที่ไม่เคยต่อเครือข่าย (air-gapped), paper wallet

ภัยจากระยะไกล (malware, เว็บปลอม)เสี่ยงโดยตรงผู้โจมตีต้องเข้าถึงตัวอุปกรณ์ เว้นแต่ผู้ใช้กดยืนยันธุรกรรมอันตรายเอง
เหมาะกับเงินใช้จ่ายรายวัน และใช้เชื่อมต่อกับ DApp (บทที่ 11)เงินเก็บระยะยาว

exchange ก็ใช้หลักเดียวกัน คือเก็บเหรียญส่วนน้อยไว้ใน hot wallet เพื่อให้ลูกค้าถอนได้ทันที และเก็บส่วนใหญ่ไว้ใน cold storage ถ้า hot wallet โดนเจาะ ความเสียหายก็จำกัดอยู่ที่เหรียญส่วนน้อยนั้น

Paper wallet: เป็น cold wallet แต่ใช้งานยาก

paper wallet คือ private key ที่พิมพ์ลงกระดาษ ส่วนใหญ่พิมพ์เป็น QR code key อยู่นอกอินเทอร์เน็ตจริง แต่เมื่อต้องการใช้เหรียญ เจ้าของต้องนำ key เข้าโปรแกรม wallet บนคอมพิวเตอร์ ตั้งแต่วินาทีนั้น key ก็กลายเป็น hot ปัญหาอื่นที่ตามมามีดังนี้

  • ผู้ใช้ที่ไม่เข้าใจ UTXO อาจนำ key เข้าโปรแกรม wallet แล้วใช้เหรียญไปเพียงบางส่วน แต่ธุรกรรมต้องใช้ UTXO ทั้งก้อน ส่วนที่เหลือจึงกลายเป็นเงินทอน (change) และโปรแกรมหลายตัวส่งเงินทอนไปยัง address ใหม่ของโปรแกรมเอง ไม่ได้ส่งกลับไปที่ address บนกระดาษ ถ้าผู้ใช้เข้าใจว่าเงินที่เหลือยังอยู่บนกระดาษ แล้วลบโปรแกรมทิ้งโดยไม่ได้สำรอง key ของเงินทอน เงินทอนก็หายไปถาวร
  • กระดาษไหม้ เปียก และหมึกซีดได้
  • เว็บไซต์ที่ใช้สร้าง key หรือเครื่องพิมพ์อาจเก็บสำเนาไว้

ปัจจุบันจึงไม่แนะนำ paper wallet แล้ว hardware wallet แก้ปัญหาตรงจุดนี้ คือเป็น cold wallet ที่ลงลายเซ็นได้โดยไม่ต้องนำ key ออกมา (หัวข้อ 14.4)

Hot และ Cold บอกตำแหน่งของ key ไม่ใช่ของเหรียญ เหรียญอยู่บน chain เสมอ คำว่า hot หรือ cold บอกเพียงว่า key ที่ควบคุมเหรียญอยู่ที่ใด ถ้าเปิดแอป wallet บนมือถือแล้วกรอก seed phrase ของ hardware wallet ลงไป key ทุกดอกก็กลายเป็น hot ทันที แม้ตัวอุปกรณ์ยังอยู่ในตู้เซฟก็ตาม

14.3Seed phrase (BIP39) และ HD wallet (BIP32 / BIP44)

ปัญหา: key มีหลายดอกและเพิ่มขึ้นเรื่อย ๆ

บทที่ 4 อธิบายว่า wallet ควรใช้ address ใหม่ทุกครั้งที่รับเงิน เพื่อไม่ให้ผู้อื่นรวบรวมประวัติการเงินของเราได้ง่าย และธุรกรรมที่มีเงินทอนก็ต้องใช้ address ใหม่อีกหนึ่งตัว wallet ที่ใช้มานานจึงมี key หลายร้อยดอก wallet รุ่นแรกของ Bitcoin สุ่ม key แต่ละดอกแยกกัน โดยสุ่มเผื่อไว้ล่วงหน้าชุดหนึ่ง (keypool) ไฟล์สำรอง (backup) จึงมีเฉพาะ key ในชุดนั้น เมื่อใช้ชุดนั้นหมด wallet จะสุ่ม key ชุดใหม่ที่ไฟล์สำรองเก่าไม่มี ถ้าเครื่องเสียแล้วกู้จากไฟล์เก่า เจ้าของจะใช้เหรียญที่รับเข้า address ใหม่เหล่านั้นไม่ได้อีก ปัญหาอีกข้อคือ private key หนึ่งดอกเป็นเลขฐานสิบหก 64 ตัว คนจดด้วยมือผิดได้ง่าย

วงการแก้ปัญหานี้ด้วยมาตรฐานสามฉบับที่ทำงานต่อกัน ทั้งสามเป็นเอกสาร BIP (Bitcoin Improvement Proposal) แต่ wallet ของ Ethereum เช่น MetaMask และ hardware wallet ทุกยี่ห้อหลักก็ใช้มาตรฐานชุดนี้

BIP39: แปลงเลขสุ่มเป็นคำ

wallet เริ่มจากสุ่มเลขขนาด 128 บิต (หรือ 256 บิต) จากแหล่งสุ่มที่ดีของอุปกรณ์ เลขนี้เรียกว่า entropy จากนั้นทำสามขั้น

  1. คำนวณ SHA-256 ของ entropy แล้วตัดบิตแรก ๆ ของผลลัพธ์มาเป็น checksum จำนวนบิตที่ตัดเท่ากับขนาด entropy หารด้วย 32 เช่น entropy 128 บิตได้ checksum 4 บิต
  2. นำ checksum ต่อท้าย entropy ได้ 132 บิต แล้วแบ่งเป็นกลุ่มละ 11 บิต ได้ 12 กลุ่ม
  3. แต่ละกลุ่มเป็นเลข 0–2047 (211 = 2048 ค่า) wallet ใช้เลขนี้เป็นลำดับในรายการคำ (wordlist) ของ BIP39 ซึ่งมี 2048 คำพอดี

ทำไมใช้คำแทนตัวเลข คนจดคำว่า apple ผิดยากกว่าจดเลขฐานสิบหก นอกจากนี้ คำในรายการภาษาอังกฤษของ BIP39 ยังมีตัวอักษร 4 ตัวแรกไม่ซ้ำกันเลย จดหรือพิมพ์เพียง 4 ตัวแรกก็ระบุคำได้

ทำไมต้องมี checksum ถ้าจดผิดหนึ่งคำ wallet มักตรวจพบเพราะ checksum ไม่ตรง ถ้าไม่มี checksum wallet จะกู้คืนเป็น wallet อื่นที่ว่างเปล่าโดยไม่เตือน และเจ้าของอาจเข้าใจว่าเหรียญโดนขโมย อย่างไรก็ตาม checksum ของ 12 คำมีเพียง 4 บิต คำที่ผิดแบบสุ่มจึงยังผ่านการตรวจได้ราว 1 ใน 16

ความปลอดภัยมาจาก entropy รายการคำเป็นข้อมูลสาธารณะ ความปลอดภัยของ seed phrase 12 คำจึงมาจาก entropy 128 บิตเท่านั้น ผู้โจมตีที่สุ่มเดาต้องลองราว 2128 แบบ ซึ่งทำไม่ได้ในทางปฏิบัติ เงื่อนไขสำคัญคือ entropy ต้องมาจากตัวสร้างเลขสุ่ม (random number generator) ที่ดี ถ้าผู้ใช้เลือกคำเองจากความชอบ หรืออุปกรณ์สุ่มเลขได้ไม่ดี ผู้โจมตีจะเดาได้เร็วกว่านี้มาก

จาก seed phrase เป็น seed

BIP39 ไม่ได้นำ entropy ไปใช้เป็น seed ตรง ๆ เพราะมีเป้าหมายสองข้อ ข้อแรกคือให้ผู้ใช้ผสม passphrase ของตัวเองเข้าไปได้ ข้อที่สองคือทำให้ผู้โจมตีเดาแต่ละครั้งได้ช้าลง wallet จึงนำข้อความของ seed phrase เข้าฟังก์ชัน PBKDF2 ที่ใช้ HMAC-SHA512 วนซ้ำ 2048 รอบ ได้ seed ขนาด 512 บิต

PBKDF2 รับข้อมูลเพิ่มอีกหนึ่งค่าเรียกว่า salt ข้อความตั้งต้นเดียวกันแต่ salt ต่างกันจะได้ผลลัพธ์ต่างกัน BIP39 กำหนดให้ salt เป็นข้อความ "mnemonic" ต่อด้วย passphrase ที่ผู้ใช้ตั้งเอง ถ้าไม่ตั้ง passphrase ส่วนนี้จะเป็นข้อความว่าง passphrase จึงเปลี่ยน seed ได้ทั้งที่ seed phrase เป็นชุดเดิม

Passphrase หรือที่มักเรียกว่า "คำที่ 25" passphrase ทุกค่าให้ seed ที่ใช้ได้เสมอ wallet จึงไม่มีทางรู้ว่าผู้ใช้พิมพ์ passphrase ผิด พิมพ์ผิดหนึ่งตัวอักษรก็ได้ wallet อีกชุดที่ว่างเปล่า ข้อดีคือคนที่ขโมย seed phrase ไปอย่างเดียวยังเข้าถึงเหรียญไม่ได้ ข้อเสียคือถ้าลืม passphrase เหรียญก็หายถาวรเหมือนกับลืม seed phrase ผู้ใช้จึงต้องสำรอง passphrase ด้วย และเก็บแยกจาก seed phrase

BIP32: HD wallet คำนวณ key ทั้งต้นไม้จาก seed เดียว

BIP32 นำ seed เข้า HMAC-SHA512 โดยใช้ข้อความ "Bitcoin seed" เป็นกุญแจของ HMAC ได้ผลลัพธ์ 512 บิต ครึ่งซ้ายเป็น master private key (256 บิต) ครึ่งขวาเป็น chain code (256 บิต) จากนั้น wallet คำนวณ key ลูก (child key) จากสามค่า ได้แก่ key แม่ (parent key), chain code ของ key แม่ และเลขลำดับ (index) ของลูก key ลูกแต่ละดอกมี chain code ของตัวเองและมีลูกต่อได้อีก จึงเกิดเป็นต้นไม้ของ key ชื่อ HD wallet (Hierarchical Deterministic) มาจากสองลักษณะนี้ คือ key เรียงเป็นลำดับชั้น และคำนวณซ้ำได้ผลเดิมทุกครั้ง สูตรนี้ใช้ chain code ด้วย ผู้ที่รู้เพียง key แม่จึงยังคำนวณ key ลูกไม่ได้

ผลที่ได้คือ wallet สร้าง address ใหม่ได้ไม่จำกัด และไฟล์สำรองไม่ต้องเปลี่ยนเลย บทที่ 4 กล่าวถึงประโยชน์ข้อนี้แล้ว คือ wallet ของ Bitcoin Core รุ่นปัจจุบันเป็นแบบ HD และ getnewaddress ให้ address ใหม่ทุกครั้งโดยไม่ต้อง backup ซ้ำ

Extended public key (xpub) และ hardened derivation

BIP32 มีคุณสมบัติที่ใช้ประโยชน์ได้มาก คือคำนวณ public key ลูกได้จาก public key แม่กับ chain code โดยไม่ต้องรู้ private key ค่าคู่นี้รวมกันเรียกว่า extended public key (xpub) ตัวอย่างเช่น ร้านค้าออนไลน์นำ xpub ไปไว้บนเซิร์ฟเวอร์ เซิร์ฟเวอร์สร้าง address ใหม่ให้ทุกคำสั่งซื้อและตรวจยอดได้เอง ถ้าเซิร์ฟเวอร์โดนเจาะ ผู้โจมตีได้เพียง xpub ซึ่งใช้จ่ายเงินไม่ได้ wallet ที่ดูยอดได้แต่ลงลายเซ็นไม่ได้แบบนี้เรียกว่า watch-only wallet

xpub ยังมีความเสี่ยงสองข้อ

  • ความเป็นส่วนตัว: ผู้ที่ได้ xpub เห็น address ทุกตัวในกิ่งนั้นและยอดเงินทั้งหมด
  • private key แม่รั่วได้: ถ้าผู้โจมตีมี xpub และได้ private key ลูกแบบปกติ (non-hardened) ไปเพียงหนึ่งดอก เขาคำนวณย้อนหา private key แม่ได้ แล้วใช้ key ทุกดอกในกิ่งนั้นได้

BIP32 จึงมี hardened derivation สำหรับ index ตั้งแต่ 231 ขึ้นไป และเขียนด้วยเครื่องหมาย ' ต่อท้ายเลขที่นับเพิ่มจาก 231 ดังนั้น 44' จึงหมายถึง index 231 + 44 ไม่ใช่ 44 key ลูกแบบ hardened คำนวณจาก private key แม่เท่านั้น xpub จึงคำนวณลูกเหล่านี้ไม่ได้ และ key ลูกที่รั่วก็ย้อนไปหา key แม่ไม่ได้ BIP44 ใช้ hardened ในสามชั้นบนของเส้นทาง ความเสียหายในบัญชีหนึ่งจึงไม่ลามไปบัญชีอื่นหรือเหรียญอื่น

BIP44: เส้นทางมาตรฐาน

BIP32 กำหนดวิธีคำนวณ แต่ไม่ได้กำหนดว่าควรใช้กิ่งใด ถ้า wallet ยี่ห้อหนึ่งเก็บ address ไว้ที่กิ่ง m/0/5 แต่อีกยี่ห้อค้นที่ m/44'/0'/0'/0/5 ผู้ใช้ที่ย้ายไปใช้อีกยี่ห้อจะเห็นยอดเป็นศูนย์ เหรียญไม่ได้หาย แต่ wallet ใหม่คำนวณ address คนละชุดจึงมองไม่เห็น BIP44 จึงกำหนดเส้นทาง 5 ชั้นต่อจาก master key (m)

เมื่อกู้คืนจาก seed phrase wallet ไม่รู้ว่าเจ้าของเคยใช้ address ไปกี่ตัว จึงคำนวณ address เรียงไปทีละตัวแล้วถามโหนดว่ามีประวัติหรือไม่ BIP44 กำหนดให้หยุดค้นเมื่อเจอ address ที่ไม่เคยใช้ติดกัน 20 ตัว ค่านี้เรียกว่า gap limit ถ้าเจ้าของเคยสร้าง address ข้ามไปไกลกว่านั้น wallet อาจหาเงินไม่เจอจนกว่าจะตั้งค่าให้ค้นต่อ

ประเด็นที่ข้อสอบชอบถาม seed phrase ชุดเดียวคุม key ของทุกเหรียญและทุกบัญชีใน wallet นั้น ทั้ง BTC และ ETH ต่างกันเพียงกิ่ง ถ้า seed phrase รั่ว ทุกอย่างรั่วพร้อมกัน อีกประเด็นหนึ่งคือ ถ้ากู้คืนใน wallet อื่นแล้วยอดเป็นศูนย์ สาเหตุที่พบบ่อยคือ derivation path หรือ passphrase ไม่ตรงกับ wallet เดิม เหรียญยังอยู่บน chain ตามเดิม

ทดลอง: จาก entropy เป็นลำดับคำ (BIP39)

เครื่องมือนี้สุ่ม entropy คำนวณ checksum ด้วย SHA-256 แล้วแบ่งเป็นกลุ่มละ 11 บิตตามขั้นตอนข้างต้น ผลลัพธ์แสดงเป็นลำดับคำ (0–2047) wallet จริงจะนำลำดับนี้ไปเปิดหาคำในรายการคำ ปุ่ม "จำลองการจดผิด 1 คำ" เปลี่ยนคำหนึ่งคำแบบสุ่ม แล้วตรวจว่า checksum ยังตรงหรือไม่ กดหลายครั้งเพื่อดูว่าตรวจพบบ่อยเพียงใด

ใช้เพื่อการเรียนเท่านั้น อย่าใช้ค่าที่สุ่มจากหน้าเว็บนี้หรือเว็บใดกับเงินจริง seed phrase ของจริงควรสร้างภายใน hardware wallet หรือ wallet ที่เชื่อถือได้ และไม่ควรปรากฏบนหน้าจอคอมพิวเตอร์ที่ต่ออินเทอร์เน็ต

14.4หลักการของ Hardware wallet: ลงลายเซ็นธุรกรรมภายในอุปกรณ์ โดย key ไม่ออกจากเครื่อง

โจทย์: ลงลายเซ็นบนคอมพิวเตอร์ที่ไว้ใจไม่ได้

หัวข้อ 14.1 แสดงว่าหลังสร้าง key แล้ว งานเดียวของ wallet ที่ต้องใช้ private key คือการลงลายเซ็น หัวข้อ 14.2 แสดงว่า key บนคอมพิวเตอร์ที่ต่ออินเทอร์เน็ตเสี่ยงต่อ malware และ paper wallet ปลอดภัยเฉพาะช่วงที่ยังไม่นำ key มาใช้ hardware wallet นำสองข้อนี้มารวมกัน อุปกรณ์ขนาดเล็กนี้สร้างและเก็บ key ไว้ภายใน รับธุรกรรมที่ยังไม่มีลายเซ็นเข้ามา ลงลายเซ็นภายในอุปกรณ์ แล้วส่งออกไปเพียงธุรกรรมที่มีลายเซ็นแล้ว คอมพิวเตอร์ยังทำทุกงานที่ไม่ต้องใช้ key ได้ตามเดิม แต่ไม่เคยเห็น key เลย แนวทางนี้เรียกว่า offline signing

  1. แอป wallet บนคอมพิวเตอร์ถามยอดจากโหนด เลือก UTXO (หรือใส่ nonce และ gas สำหรับ Ethereum) แล้วสร้างธุรกรรมที่ยังไม่มีลายเซ็น ฝั่ง Bitcoin มักส่งในรูปแบบมาตรฐาน PSBT (Partially Signed Bitcoin Transaction, BIP174)
  2. คอมพิวเตอร์ส่งธุรกรรมเข้าอุปกรณ์ผ่าน USB, Bluetooth, QR code หรือ microSD
  3. อุปกรณ์อ่านธุรกรรมแล้วแสดง address ปลายทาง จำนวนเงิน และค่าธรรมเนียมบน หน้าจอของอุปกรณ์เอง ผู้ใช้ตรวจแล้วกดปุ่มบนอุปกรณ์ อุปกรณ์จึงลงลายเซ็นด้วย private key ภายใน
  4. อุปกรณ์ส่งธุรกรรมที่มีลายเซ็นกลับไปยังคอมพิวเตอร์
  5. แอปบนคอมพิวเตอร์ broadcast ธุรกรรมเข้าเครือข่าย

ถ้าคอมพิวเตอร์มี malware ผู้โจมตีดูยอดและประวัติได้ และอาจแก้ธุรกรรมก่อนส่งเข้าอุปกรณ์ แต่คัดลอก key ไม่ได้เพราะ key ไม่เคยออกมา และสร้างลายเซ็นเองไม่ได้ถ้าผู้ใช้ไม่กดยืนยันบนอุปกรณ์

ทำไมต้องมีหน้าจอและปุ่มบนอุปกรณ์

ถ้าอุปกรณ์ลงลายเซ็นทุกอย่างที่คอมพิวเตอร์ส่งมา malware ก็เพียงเปลี่ยน address ปลายทางเป็นของผู้โจมตีแล้วส่งเข้าไป อุปกรณ์จะลงลายเซ็นให้โดยไม่มีใครรู้ หน้าจอคอมพิวเตอร์ก็เชื่อไม่ได้ เพราะ malware แสดง address เดิมบนหน้าจอได้ ทั้งที่ส่ง address ใหม่เข้าอุปกรณ์ hardware wallet จึงต้องมีหน้าจอและปุ่มของตัวเองที่ malware บนคอมพิวเตอร์ควบคุมไม่ได้ ผู้ใช้จะรู้ได้แน่ว่ากำลังลงลายเซ็นอะไรก็จากหน้าจอนี้เท่านั้น

หลักเดียวกันใช้กับการรับเงินด้วย malware อาจแสดง address ของผู้โจมตีในแอปแทน address ของเรา ก่อนให้ address แก่ผู้โอนเงินก้อนใหญ่ ผู้ใช้ควรสั่งให้อุปกรณ์แสดง address รับเงินบนหน้าจอของอุปกรณ์แล้วเทียบให้ตรงกัน ทั้งสองกรณี ถ้าผู้ใช้กดยืนยันโดยไม่อ่านหน้าจออุปกรณ์ hardware wallet ก็ป้องกันอะไรไม่ได้

ทำไมต้องมี secure element และ PIN

ภัยอีกแบบคือมีคนขโมยตัวอุปกรณ์ไป ถ้า key เก็บอยู่ในหน่วยความจำธรรมดา ผู้โจมตีที่มีเครื่องมืออาจแกะชิปแล้วอ่านค่าได้ hardware wallet หลายรุ่นจึงเก็บ key ใน secure element secure element เป็นชิปประเภทเดียวกับที่ใช้ในบัตรธนาคารแบบชิปและซิมการ์ด ชิปนี้ออกแบบมาให้ทนการโจมตีทางกายภาพสองแบบ แบบแรกคือ side-channel attack ผู้โจมตีวัดกำลังไฟหรือคลื่นแม่เหล็กไฟฟ้าที่ชิปปล่อยออกมาระหว่างคำนวณ ค่าที่วัดได้เปลี่ยนไปตามบิตของ key ผู้โจมตีจึงใช้ค่านี้เดา key ได้ แบบที่สองคือ fault injection ผู้โจมตีรบกวนแรงดันไฟให้ชิปทำงานผิดพลาด เช่น ข้ามขั้นตรวจ PIN หรือส่งข้อมูลในหน่วยความจำออกมา secure element มีวงจรที่ลดสัญญาณรั่วและตรวจจับการรบกวนแบบนี้

อุปกรณ์ยังล็อกด้วย PIN และหลายรุ่นล้างข้อมูลทั้งหมดเมื่อใส่ PIN ผิดครบจำนวนครั้งที่กำหนด การล้างข้อมูลไม่ทำให้เจ้าของเสียเงิน เพราะเจ้าของกู้คืนจาก seed phrase ได้ แต่ผู้ขโมยจะเดา PIN ไปเรื่อย ๆ ไม่ได้ hardware wallet บางรุ่นใช้ microcontroller ทั่วไปแทน secure element และเคยมีรายงานว่าผู้ที่ได้ตัวเครื่องไปและมีอุปกรณ์เฉพาะทางดึง seed ออกมาได้ สำหรับรุ่นแบบนี้ ผู้ใช้ควรตั้ง passphrase เพิ่ม เพราะ passphrase ไม่ได้เก็บอยู่ในเครื่อง

Air-gapped signing

hardware wallet บางรุ่นไม่ต่อสายกับคอมพิวเตอร์เลย แต่รับส่งธุรกรรมผ่าน QR code หรือการ์ด microSD แทน แนวทางนี้เรียกว่า air-gapped ข้อดีคือตัดช่องทางที่ malware อาจโจมตีอุปกรณ์ผ่านสาย USB และผู้ใช้เห็นได้ชัดว่ามีข้อมูลอะไรผ่านเข้าออกบ้าง PSBT ในข้อ 1 ช่วยให้ทำแบบนี้ได้ เพราะเป็นรูปแบบมาตรฐานที่ทั้งแอปและอุปกรณ์อ่านได้

Ethereum: ปัญหา blind signing

ธุรกรรมโอน BTC หรือ ETH ธรรมดาแสดงบนหน้าจอได้ง่าย มีเพียง address และจำนวนเงิน แต่ธุรกรรมที่เรียก smart contract มี data เป็น function selector ตามด้วยพารามิเตอร์ (บทที่ 5) ถ้าอุปกรณ์ถอดความหมาย (decode) ของ data ไม่ได้ ก็แสดงได้เพียงค่าแฮชหรือเลขฐานสิบหกยาว ๆ ผู้ใช้จึงลงลายเซ็นโดยไม่รู้ว่าธุรกรรมทำอะไร เรียกว่า blind signing ผู้ใช้อาจกำลังยืนยัน approve ให้ผู้โจมตีถอนโทเคนทั้งหมด (บทที่ 12) โดยไม่รู้ตัว ลายเซ็นข้อความนอก chain (off-chain) ตาม EIP-712 ก็มีปัญหาเดียวกัน ลายเซ็นแบบนี้ไม่ใช่ธุรกรรมและไม่เสีย gas ผู้ใช้จึงมักคิดว่าไม่มีผล แต่ลายเซ็น permit ให้สิทธิ์ใช้โทเคนได้เหมือน approve คนที่ได้ลายเซ็นไปส่งลายเซ็นนั้นเข้า contract เองได้ แล้วโอนโทเคนออกตามสิทธิ์นั้น

ทางแก้คือ clear signing อุปกรณ์ถอดความหมายของ data แล้วแสดงชื่อฟังก์ชันและพารามิเตอร์ในรูปที่คนอ่านเข้าใจ ถ้าอุปกรณ์แสดงรายละเอียดไม่ได้ ผู้ใช้ไม่ควรยืนยัน โดยเฉพาะเมื่อธุรกรรมมาจากเว็บไซต์ที่ไม่คุ้นเคย

Hardware wallet กันไม่ให้ key รั่ว แต่ตัดสินใจแทนผู้ใช้ไม่ได้ เหตุการณ์ที่ Bybit (กุมภาพันธ์ 2025) เป็นตัวอย่างที่มักยกกัน ผู้โจมตีแก้หน้าเว็บที่ทีมงานใช้สร้างธุรกรรมของ cold wallet แบบ multisig ผู้ลงลายเซ็นทุกคนเห็นธุรกรรมโอนเงินตามปกติบนหน้าเว็บ แต่ธุรกรรมที่ส่งเข้า hardware wallet จริงเป็นคำสั่งเปลี่ยน smart contract ของ multisig wallet (Safe) ให้ไปใช้โค้ดของผู้โจมตี และหน้าจออุปกรณ์แสดงรายละเอียดได้ไม่ครบ เมื่อลงลายเซ็นครบตามจำนวน ผู้โจมตีก็ควบคุม wallet นั้นได้ แล้วโอน ETH และโทเคนที่อิง ETH มูลค่าราว 1.4–1.5 พันล้านดอลลาร์ออกไป key ไม่ได้รั่วเลย แต่ผู้ถือ key ยืนยันธุรกรรมที่ตนไม่ได้อ่านจริง

กลุ่มที่ 1: ภัยที่มุ่งเอา seed phrase

ภัยวิธีการวิธีป้องกัน
Phishing ขอ seed phraseเว็บไซต์ แอป หรือ "ฝ่ายช่วยเหลือ" ปลอม แจ้งว่าบัญชีมีปัญหา แล้วให้กรอก seed phrase เพื่อ "ยืนยัน" หรือ "ซิงก์" walletไม่กรอก seed phrase ลงเว็บไซต์ แชต หรือแอปที่ขอมา hardware wallet ส่วนใหญ่ให้กรอก seed phrase บนตัวอุปกรณ์ตอนกู้คืนเท่านั้น บางรุ่น เช่น Trezor Model One ให้พิมพ์คำผ่านคอมพิวเตอร์ตามลำดับที่อุปกรณ์สลับไว้ ซึ่งทำได้เฉพาะในขั้นตอนกู้คืนของแอปทางการ ผู้ผลิตไม่มีเหตุผลใดที่ต้องขอ seed phrase
อุปกรณ์ปลอมหรือโดนดัดแปลง (supply chain attack)ขายอุปกรณ์ผ่านร้านที่ไม่ใช่ตัวแทน หรือส่งอุปกรณ์ "ทดแทน" มาทางไปรษณีย์ บางกล่องแนบการ์ดที่พิมพ์ seed phrase มาให้ใช้ซื้อจากผู้ผลิตหรือตัวแทนที่ได้รับอนุญาต ให้อุปกรณ์สร้าง seed phrase ใหม่เองทุกครั้ง ถ้ามี seed phrase มาในกล่อง ให้ถือว่าเป็นของปลอม
สำรองแบบดิจิทัลถ่ายรูป seed phrase แล้วรูปซิงก์ขึ้นคลาวด์ จดในแอปโน้ต หรือส่งอีเมลหาตัวเอง แล้วบัญชีคลาวด์หรืออีเมลโดนเจาะจดด้วยมือบนกระดาษหรือแผ่นโลหะ ไม่เก็บสำเนาในอุปกรณ์ที่ต่ออินเทอร์เน็ต
คนใกล้ตัวเห็นการ์ด seed phraseเก็บการ์ดไว้กับตัวอุปกรณ์ หรือในที่ที่คนในบ้านหรือที่ทำงานเปิดดูได้เก็บในที่ที่คนอื่นเข้าถึงไม่ได้ และพิจารณาตั้ง passphrase เพิ่ม
ข้อมูลส่วนตัวรั่วก็นำไปสู่การขโมยเหรียญได้ ในปี 2020 ฐานข้อมูลลูกค้าของ Ledger ผู้ผลิต hardware wallet รายใหญ่ รั่วออกไป ข้อมูลที่รั่วมีชื่อ ที่อยู่ และเบอร์โทรศัพท์ ไม่มี key ของลูกค้า แต่หลังจากนั้นลูกค้าจำนวนมากได้รับอีเมลและ SMS ปลอม และมีรายงานว่าบางรายได้รับอุปกรณ์ปลอมทางไปรษณีย์ที่ออกแบบมาเพื่อขโมย seed phrase ผู้โจมตีรู้แน่ชัดว่าคนเหล่านี้ถือเหรียญ จึงส่ง phishing ได้ตรงเป้า

กลุ่มที่ 2: ภัยที่หลอกให้ลงลายเซ็น

ภัยวิธีการวิธีป้องกัน
Malware เปลี่ยน address (clipboard hijacker)ผู้ใช้คัดลอก address ผู้รับ แล้ว malware แทนที่ด้วย address ของผู้โจมตี ซึ่งมักมีตัวอักษรต้นและท้ายคล้ายกันตรวจ address ทั้งหมดบนหน้าจอ hardware wallet ไม่ใช่แค่ตัวแรกและตัวท้าย
Address poisoningผู้โจมตีสร้าง address ที่ต้นและท้ายเหมือน address ที่เราเคยโอนให้ แล้วส่งธุรกรรมมูลค่าศูนย์หรือน้อยมากเข้ามา address ปลอมจึงปรากฏในประวัติ ผู้ใช้คัดลอกจากประวัติไปใช้ครั้งต่อไปไม่คัดลอก address จากประวัติธุรกรรม ใช้สมุด address (address book) หรือขอ address จากผู้รับโดยตรง และโอนจำนวนน้อยทดสอบก่อนเมื่อเป็นยอดใหญ่
Approve หรือลายเซ็นที่ให้สิทธิ์เกินจำเป็น (wallet drainer)DApp ปลอมขอให้ approve โทเคน หรือ setApprovalForAll ของ NFT (บทที่ 12) หรือขอลายเซ็น permit แล้วใช้สิทธิ์นั้นโอนทรัพย์สินออกภายหลังอ่านสิ่งที่ลงลายเซ็นบนหน้าจออุปกรณ์ ปฏิเสธเมื่อเป็น blind signing ใช้ hot wallet แยกที่มีเงินน้อยสำหรับทดลอง DApp และเพิกถอนสิทธิ์ (revoke) ที่ไม่ใช้แล้ว

กลุ่มที่ 3: ภัยที่ทำให้เจ้าของเข้าถึง key ไม่ได้

ภัยวิธีการหรือสาเหตุวิธีป้องกัน
seed phrase เสียหายหรือหายไฟไหม้ น้ำท่วม หมึกซีด หรือทิ้งไปโดยไม่ตั้งใจเก็บสำเนามากกว่าหนึ่งชุดในสถานที่ต่างกัน ใช้แผ่นโลหะ และทดลองกู้คืนจาก seed phrase ก่อนโอนเงินก้อนใหญ่เข้า
ลืม passphrase หรือ derivation pathไม่ได้จด passphrase หรือไม่ได้จดว่า wallet เดิมใช้ derivation path ใด เมื่อกู้คืนใน wallet อื่นจึงเห็นยอดเป็นศูนย์จดไว้ว่าใช้ wallet ใดและตั้งค่าอย่างไร และสำรอง passphrase แยกจาก seed phrase
เจ้าของเสียชีวิตหรือไร้ความสามารถทายาทไม่รู้ว่ามีเหรียญ หรือไม่รู้วิธีเข้าถึง เหรียญจึงหายถาวรวางแผนมรดก บอกวิธีหาข้อมูลแก่คนที่ไว้ใจ หรือใช้ multisig ที่ทายาทถือ key บางดอก

ภัยอีกแบบไม่เข้ากลุ่มใดข้างต้น คือการบังคับข่มขู่ทางกายภาพ (wrench attack) ในกรณีนี้ key ไม่ได้รั่วและเจ้าของก็ยังเข้าถึง key ได้ แต่ผู้ร้ายบังคับให้เจ้าของโอนเหรียญด้วยมือตัวเอง hardware wallet จึงช่วยไม่ได้ วิธีลดความเสี่ยงคือไม่เปิดเผยยอดถือครอง และใช้ passphrase ซ่อน wallet หลักไว้ เจ้าของเก็บเงินจำนวนน้อยใน wallet ที่ไม่มี passphrase และยอมเปิด wallet นี้ให้ผู้ร้ายดูได้ ส่วน wallet หลักต้องใส่ passphrase จึงจะเห็น อีกวิธีคือใช้ multisig ที่ key อยู่หลายสถานที่ เจ้าของจึงโอนคนเดียวทันทีไม่ได้

Multisig: ตัดจุดล้มเหลวเดียว

ทุกวิธีข้างต้นยังมี seed phrase ชุดเดียวเป็นจุดล้มเหลวเดียว (single point of failure) seed phrase นั้นรั่วก็เสียทั้งหมด หายก็เสียทั้งหมด multisig (multi-signature) แก้ปัญหานี้โดยกำหนดให้ใช้ลายเซ็นจาก key หลายดอก ตัวอย่างเช่นแบบ 2-of-3 เจ้าของมี key 3 ดอกเก็บในอุปกรณ์และสถานที่ต่างกัน การใช้เหรียญแต่ละครั้งต้องมีลายเซ็นอย่างน้อย 2 ดอก

  • key หนึ่งดอกรั่ว: ผู้โจมตีมีลายเซ็นเพียงหนึ่งดอก จึงยังใช้เหรียญไม่ได้
  • key หนึ่งดอกหาย: เจ้าของยังใช้อีกสองดอกย้ายเหรียญไป wallet ใหม่ได้

Bitcoin ทำ multisig ใน Script ได้โดยตรง มักอยู่ใน address แบบ P2SH หรือ P2WSH ส่วน Ethereum ทำผ่าน smart contract wallet เช่น Safe ข้อแลกเปลี่ยนคือตั้งค่าและกู้คืนยากกว่า ฝั่ง Bitcoin ผู้ใช้ต้องสำรองข้อมูลการตั้งค่าของ multisig ด้วย เช่น xpub ของทุกดอกและจำนวนลายเซ็นที่ต้องใช้ ไม่ใช่สำรองเพียง seed phrase ของแต่ละดอก เหตุผลคือ address ของ multisig คำนวณจาก script ที่มี public key ครบทุกดอกและจำนวนลายเซ็นที่กำหนด ถ้าเหลือ seed phrase เพียงสองชุดจากสามชุด และไม่มี xpub ของดอกที่สาม wallet จะสร้าง script และ address เดิมไม่ได้ จึงหาเหรียญไม่เจอ แม้จะมี key ครบสองดอกตามเงื่อนไขก็ตาม กรณี Bybit ในหัวข้อ 14.4 ยังแสดงว่า multisig ไม่ช่วย ถ้าผู้ลงลายเซ็นทุกคนเห็นข้อมูลเดียวกันจากหน้าเว็บที่โดนแก้ แล้วยืนยันโดยไม่ได้ตรวจบนอุปกรณ์

กฎที่ควรจำ
  1. กรอก seed phrase เฉพาะตอนกู้คืน และกรอกในอุปกรณ์หรือแอป wallet ที่ตัวเองเลือกและตรวจแหล่งที่มาแล้วเท่านั้น ถ้าใช้ hardware wallet ให้กรอกผ่านขั้นตอนกู้คืนของอุปกรณ์ ใครขอ seed phrase ไม่ว่าด้วยเหตุผลใด ให้ถือว่าเป็นผู้โจมตี
  2. ให้อุปกรณ์สร้าง seed phrase เอง ไม่ใช้ seed phrase ที่คนอื่นเตรียมไว้ให้
  3. สำรอง seed phrase แบบออฟไลน์ มากกว่าหนึ่งชุด และทดลองกู้คืนก่อนใช้จริง
  4. เชื่อเฉพาะสิ่งที่แสดงบนหน้าจอของอุปกรณ์ ถ้าอ่านไม่เข้าใจหรือแสดงไม่ครบ อย่ากดยืนยัน
  5. แยกเงินเก็บ (cold) ออกจากเงินใช้จ่ายและการทดลอง DApp (hot)

สรุปท้ายบท

  • โจทย์: ผู้ถือ private key คือเจ้าของเหรียญ และไม่มีตัวกลางกู้บัญชีหรือย้อนธุรกรรมให้ เจ้าของจึงต้องป้องกัน key ทั้งจากการหายและการรั่ว ในขณะที่ key ยังต้องพร้อมลงลายเซ็น
  • 14.1: เหรียญอยู่บน chain เสมอ wallet เก็บเพียง private key และหลังสร้าง key แล้ว งานเดียวที่ต้องใช้ private key คือการลงลายเซ็น custodial wallet ให้ผู้ให้บริการถือ key แทน จึงนำตัวกลางกลับมา (Not your keys, not your coins)
  • 14.2: Hot wallet เก็บ key บนอุปกรณ์ที่ต่ออินเทอร์เน็ต สะดวกแต่เสี่ยงต่อภัยระยะไกล Cold wallet เก็บ key นอกอินเทอร์เน็ต เหมาะกับเงินเก็บระยะยาว paper wallet เป็น cold ก็จริง แต่ key กลายเป็น hot ทันทีที่นำมาใช้
  • 14.3: BIP39 แปลง entropy 128–256 บิตพร้อม checksum เป็นคำ 12–24 คำ ขั้นนี้แปลงกลับได้ จากนั้นใช้ PBKDF2 แปลงเป็น seed 512 บิต ซึ่งย้อนกลับไม่ได้ BIP32 คำนวณ key ทั้งต้นไม้จาก seed เดียว และมี xpub กับ hardened derivation BIP44 กำหนดเส้นทาง m/purpose'/coin_type'/account'/change/address_index wallet ต่างยี่ห้อจึงกู้คืนได้ตรงกัน
  • 14.4: hardware wallet ลงลายเซ็นภายในอุปกรณ์และส่งออกเพียงธุรกรรมที่มีลายเซ็น หน้าจอและปุ่มของอุปกรณ์ทำให้ผู้ใช้เห็นได้ถ้า malware แก้ธุรกรรม secure element และ PIN ป้องกันผู้ที่ได้ตัวเครื่องไป แต่ถ้าผู้ใช้กดยืนยันโดยไม่อ่าน หรือยอมลงลายเซ็นแบบ blind signing อุปกรณ์ก็ลงลายเซ็นให้ตามคำสั่ง
  • 14.5: ผู้โจมตีเลือกเจาะที่คนและกระบวนการ ไม่ใช่ที่คณิตศาสตร์ ภัยแบ่งเป็นสามกลุ่ม คือเอา seed phrase หลอกให้ลงลายเซ็น และทำให้เจ้าของเข้าถึง key ไม่ได้ ส่วน wrench attack บังคับเจ้าของโดยตรง multisig ช่วยตัดจุดล้มเหลวเดียว

แบบฝึกหัด

1. โทรศัพท์ที่ติดตั้ง MetaMask หาย แต่เจ้าของจด seed phrase ไว้ ETH ในบัญชีหายไปด้วยหรือไม่ และเจ้าของควรทำอะไรต่อ

ดูเฉลย
ไม่หาย เพราะ ETH อยู่ใน world state บน chain ไม่ได้อยู่ในโทรศัพท์ เจ้าของติดตั้ง wallet บนเครื่องใหม่แล้วกู้คืนจาก seed phrase ก็ได้ key ชุดเดิม แต่ถ้าผู้เก็บได้ปลดล็อกโทรศัพท์ได้ เขาก็อาจเข้าถึง key ได้เช่นกัน เจ้าของจึงควรสร้าง seed phrase ชุดใหม่แล้วโอนเงินทั้งหมดไปยัง address ใหม่โดยเร็ว

2. seed phrase 24 คำตาม BIP39 มี entropy กี่บิต

  1. ก. 128 บิต
  2. ข. 192 บิต
  3. ค. 256 บิต
  4. ง. 264 บิต
ดูเฉลย
ค. 24 คำ × 11 บิต = 264 บิต ประกอบด้วย entropy 256 บิตและ checksum 256 / 32 = 8 บิต ข้อ ง คือจำนวนบิตรวมที่นับ checksum ด้วย

3. checksum ใน seed phrase ช่วยอะไร และทำไมจดผิดหนึ่งคำใน seed phrase 12 คำจึงอาจยังผ่านการตรวจได้

ดูเฉลย
checksum ช่วยให้ wallet ตรวจพบว่าคำผิด แทนที่จะกู้คืนเป็น wallet อื่นที่ว่างเปล่าโดยไม่เตือน แต่ seed phrase 12 คำมี checksum เพียง 4 บิต ซึ่งมี 16 ค่าที่เป็นไปได้ คำที่ผิดแบบสุ่มจึงมีโอกาสราว 1 ใน 16 ที่ checksum ตรงโดยบังเอิญ

4. ข้อใดไม่ใช่ cold wallet

  1. ก. Hardware wallet
  2. ข. Paper wallet ที่ยังไม่เคยนำ key ไปใช้
  3. ค. MetaMask บนเบราว์เซอร์
  4. ง. คอมพิวเตอร์ที่ไม่เคยต่อเครือข่าย ใช้ลงลายเซ็นอย่างเดียว
ดูเฉลย
ค. MetaMask เก็บ key ไว้ในเบราว์เซอร์บนเครื่องที่ต่ออินเทอร์เน็ต จึงเป็น hot wallet เกณฑ์แบ่ง hot กับ cold คือ private key อยู่บนอุปกรณ์ที่ต่ออินเทอร์เน็ตหรือไม่

5. derivation path ใดคือ address ของบัญชีที่สองใน MetaMask

  1. ก. m/44'/0'/0'/0/1
  2. ข. m/44'/60'/1'/0/0
  3. ค. m/44'/60'/0'/0/1
  4. ง. m/44'/60'/0'/1/0
ดูเฉลย
ค. coin_type ของ Ethereum คือ 60' และ MetaMask เพิ่มบัญชีใหม่ที่ชั้น address_index ข้อ ก เป็นกิ่งของ Bitcoin (coin_type 0') ข้อ ข เพิ่มที่ชั้น account' ซึ่งเป็นรูปแบบที่ wallet บางยี่ห้อใช้ แต่ไม่ใช่ของ MetaMask ข้อ ง ใช้ change = 1 ซึ่ง Ethereum ไม่ใช้เพราะ Account model ไม่มีเงินทอน

6. ร้านค้านำ xpub ของบัญชีไปไว้บนเซิร์ฟเวอร์เพื่อสร้าง address รับเงิน ได้ประโยชน์อะไร และถ้าพนักงานคนหนึ่งได้ private key ของ address รับเงินไปหนึ่งดอก จะเกิดอะไรขึ้น

ดูเฉลย
เซิร์ฟเวอร์สร้าง address ใหม่ให้ทุกคำสั่งซื้อและตรวจยอดได้โดยไม่ต้องมี private key ถ้าเซิร์ฟเวอร์โดนเจาะ ผู้โจมตีเห็นยอดและประวัติแต่ใช้เงินไม่ได้ อย่างไรก็ตาม address รับเงินอยู่ในชั้นที่ไม่ใช่ hardened ถ้าใครมีทั้ง xpub และ private key ลูกหนึ่งดอก ก็คำนวณย้อนหา private key ของบัญชีได้ และใช้เงินทุก address ในบัญชีนั้นได้ ส่วนบัญชีอื่นหรือเหรียญอื่นไม่เสียหาย เพราะชั้น account' ขึ้นไปเป็น hardened

7. คอมพิวเตอร์ของผู้ใช้ติด malware และผู้ใช้โอน BTC ด้วย hardware wallet hardware wallet ป้องกันอะไรได้และป้องกันอะไรไม่ได้

ดูเฉลย
ป้องกันได้: malware คัดลอก private key ไม่ได้เพราะ key ไม่ออกจากอุปกรณ์ และสร้างลายเซ็นเองไม่ได้ถ้าผู้ใช้ไม่กดยืนยัน ป้องกันไม่ได้: malware แก้ address ปลายทางในธุรกรรมที่ส่งเข้าอุปกรณ์ได้ ถ้าผู้ใช้ไม่ตรวจ address บนหน้าจออุปกรณ์แล้วกดยืนยัน เงินก็ไปถึงผู้โจมตี นอกจากนี้ malware ยังเห็นยอดและประวัติธุรกรรมได้

8. ทำไม hardware wallet ต้องมีหน้าจอของตัวเอง ทั้งที่คอมพิวเตอร์ก็แสดงรายละเอียดธุรกรรมได้อยู่แล้ว

ดูเฉลย
malware ควบคุมหน้าจอคอมพิวเตอร์ได้ จึงแสดง address ที่ถูกต้องบนหน้าจอ แต่ส่งธุรกรรมที่มี address ของผู้โจมตีเข้าอุปกรณ์ได้ หน้าจอของอุปกรณ์แสดงข้อมูลจากธุรกรรมที่อุปกรณ์กำลังจะลงลายเซ็นจริง และ malware บนคอมพิวเตอร์แก้หน้าจอนี้ไม่ได้ จึงเป็นจุดเดียวที่ผู้ใช้เชื่อได้

9. ผู้ใช้กู้คืน seed phrase 12 คำที่ถูกต้องใน wallet ยี่ห้อใหม่ แต่ยอดแสดงเป็นศูนย์ สาเหตุที่เป็นไปได้มีอะไรบ้าง

ดูเฉลย
(1) derivation path ไม่ตรงกัน เช่น wallet เดิมใช้ m/84'/0'/0' แต่ wallet ใหม่ค้นที่ m/44'/0'/0' (2) wallet เดิมตั้ง passphrase ไว้ แต่ตอนกู้คืนไม่ได้ใส่หรือใส่ผิด ซึ่ง wallet ไม่มีทางเตือนได้ (3) address ที่มีเงินอยู่ไกลเกิน gap limit 20 ตัว (4) wallet ใหม่ต่อกับเครือข่ายอื่น เช่น testnet ในทุกกรณี เหรียญยังอยู่บน chain เพียงแต่ wallet ใหม่ยังคำนวณไม่ถึง address ที่มีเงิน

10. ผู้ใช้ตั้ง multisig แบบ 2-of-3 ต่อมา key A รั่วไปถึงผู้โจมตี และ key B หายเพราะอุปกรณ์เสีย ผู้ใช้ยังรักษาเหรียญได้หรือไม่ ควรทำอย่างไร
